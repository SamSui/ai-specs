## 一、问题根因与格式现状分析

### 1.1 现有主任务清单格式问题

[某项目]Phase1产生的主任务清单存在以下格式不一致问题：

| 文件 | 问题表现 | 严重程度 |
|------|---------|---------|
| `tasks-20260404.md` | 纯表格形式，无任务描述，无门禁表 | 🔴 高 |
| `tasks-20260404-7.md` | 包含问题分析、任务详情、门禁表，但无标准章节结构 | 🟡 中 |
| `tasks-20260405-2.md` | 包含规范草稿，但未独立成文，混在任务详情中 | 🟡 中 |

### 1.2 格式不一致导致的问题

| 问题 | 后果 |
|------|------|
| 章节结构不统一 | 评审时难以快速定位关键信息 |
| 缺少门禁表 | 无法快速判断里程碑是否达成 |
| 任务描述格式散乱 | subagent拆解任务卡片时理解成本高 |
| 与任务卡片边界不清 | 主任务清单与任务卡片内容重复或遗漏 |

## 二、主任务清单 vs 任务卡片：核心区别

### 2.1 概念对比

| 维度 | 主任务清单 | 任务卡片 |
|------|-----------|---------|
| **粒度** | 里程碑级/项目级，面向[项目负责人]审批 | 单个subagent任务，面向主agent调度 |
| **格式** | Markdown文档（多章节结构） | 独立.md文件（固定字段结构） |
| **用途** | 调度入口、里程碑规划、进度跟踪 | subagent执行依据、验收标准 |
| **审批流程** | [项目负责人]审批 → 主agent拆解 → subagent执行 | 主agent审批 → subagent执行 → Sub-task Review |
| **更新频率** | 每轮MilestoneReview后更新 | 每个任务完成后可能更新 |
| **发布范围** | [项目负责人]+主agent | 仅主agent |

### 2.2 层次关系图

```
┌─────────────────────────────────────────────────────┐
│  [项目负责人]指令 / 新需求                                   │
│       ↓                                             │
│  主任务清单（里程碑级）← 本规范约束                   │
│       ↓ [项目负责人]审批                                     │
│  拆解为多个任务卡片（subagent级）← SPEC-TASKCARD规范约束      │
│       ↓ 主agent调度                                  │
│  subagent执行 → Sub-task Review → 主agent评审             │
│       ↓                                             │
│  MilestoneReview → 发现新问题                       │
│       ↓                                             │
│  回到主任务清单（迭代闭环）                          │
└─────────────────────────────────────────────────────┘
```

### 2.3 内容分工

| 内容 | 主任务清单 | 任务卡片 |
|------|-----------|---------|
| 现状评估 | ✅ 必须（章节一） | ❌ 不需要 |
| 问题分析 | ✅ 必须（来自上轮MilestoneReview） | ❌ 不需要 |
| 任务列表 | ✅ 表格形式，高层级 | ✅ 详细描述，独立文件 |
| 任务详情 | ✅ 简要描述，引用任务卡片 | ✅ 完整描述，含验收标准 |
| 门禁表 | ✅ **必须章节四** | ❌ 不需要 |
| 迭代闭环 | ✅ 体现流程 | ❌ 不需要 |

### 2.4 目录结构

```
tasks/
└── {YYYYMMDD-M?-标题}/           # 主任务目录
    ├── index.md                  # 主任务清单(本文要约束的就是这个文件的编写)
    ├── master-track.md           # 任务跟踪表
    ├── cards/                    # 任务卡片(本文描述的任务卡片就是这个目录里的.md文件)
    │   └── T-XXX-001.md
    └── reviews/                  # 评审报告目录（任务卡片执行过程中由Reviewer生成）
        ├── T-XXX-001-review.md   # 单任务评审报告
        ├── T-XXX-002-review.md
```

**命名规范**：
- 单任务报告：`{T-XXX-###}-review.md`
- 评审索引：`reviews/index.md`

## 三、必须章节结构

主任务清单必须包含以下 **4个标准章节**：

### 3.1 章节清单

| 章节号 | 章节名称 | 必要性 | 说明 |
|--------|---------|--------|------|
| 一 | 现状评估 | ✅ 必须 | 上轮遗留问题 + 本轮任务来源 |
| 二 | 任务总览 | ✅ 必须 | 任务列表表格（ID/名称/优先级/负责人/截止/依赖/状态） |
| 三 | 任务详情 | ✅ 必须 | 每个任务的简要描述，引用任务卡片 |
| 四 | Milestone Checkpoint 门禁 | ✅ **必须（关键）** | 门禁项要求 + 对应任务 + 当前状态 |

### 3.2 章节内容要求

**章节一：现状评估**
- 上轮遗留问题清单（问题/等级/状态）
- 本轮任务来源说明（MilestoneReview产出/新增需求/技术债务）
- 与上轮评审报告的关联

**章节二：任务总览**
- 表格形式，列：ID、任务名称、优先级、负责人、截止时间、依赖、状态
- 优先级标记：🔴P0（阻塞门禁）/🟡P1（重要但不阻塞）/🟡P2（可延后）

**章节三：任务详情**
- 每个任务的简要描述（不是完整任务卡片）
- 引用对应的任务卡片路径
- 关键验收标准

**章节四：Milestone Checkpoint 门禁（必备章节）**
- 门禁项表格（门禁项/要求/对应任务/当前状态）
- 状态标记：✅通过/🟡进行中/❌未通过
- **此章节为主任务清单特有，任务卡片不包含**

| 上游 | 接口 | 下游 | 说明 |

## 六、编写检查清单

完成主任务清单编写后，作者必须逐项检查：

- [ ] **版本信息完整**：包含版本号、创建日期、创建人、基于什么
- [ ] **章节数≥4**：必须包含现状评估、任务总览、任务详情、门禁表
- [ ] **现状评估包含上轮问题**：列出上轮遗留问题及状态
- [ ] **任务总览表格完整**：列：ID/名称/优先级/负责人/截止/依赖/状态
- [ ] **任务详情引用任务卡片**：每个任务关联到对应的任务卡片文件
- [ ] **门禁表包含状态列**：✅/🟡/❌ 标记当前进度
- [ ] **门禁项与任务对应**：每个门禁项关联到具体任务ID
- [ ] **依赖关系正确**：任务依赖存在且合理，无循环依赖
- [ ] **优先级标记清晰**：🔴P0/🟡P1/🟡P2 清晰标注
- [ ] **路径为绝对路径**：所有文件路径使用绝对路径
- [ ] **格式语法正确**：Markdown语法正确，表格/代码块格式规范

## 八、常见问题FAQ

### Q1: 主任务清单和任务卡片可以合并吗？

**不可以**。主任务清单是[项目负责人]审批的里程碑级规划，任务卡片是subagent执行的具体依据。两者粒度不同、用途不同、审批流程不同。正确流程：主任务清单 → 拆解为多个任务卡片 → 分别执行。

### Q2: 门禁表一定要单独成节吗？

**是的**。门禁表是主任务清单的**必备章节**（章节四），用于快速判断里程碑是否达成。任务卡片不包含此章节，这是主任务清单区别于任务卡片的核心特征。

### Q3: 如果任务很少，还需要完整的4个章节吗？

**需要**。即使只有1-2个任务，也必须包含完整的4个章节结构。这是规范一致性的要求。可以通过简化每个章节的内容来减少总体篇幅，但结构不能缺失。

### Q4: 主任务清单可以包含多个里程碑吗？

**不推荐**。建议每个主任务清单对应一个里程碑（M1/M2/M3）。多个里程碑混在一起会导致门禁表混乱，难以快速判断各里程碑状态。

### Q5: 与SPEC-TASKCARD任务卡片规范的关系是什么？

SPEC-TASKCARD定义任务卡片的格式规范，SPEC-MASTERTASK定义主任务清单的格式规范。两者是上下游关系：主任务清单拆解为多个任务卡片，任务卡片遵循SPEC-TASKCARD规范。
