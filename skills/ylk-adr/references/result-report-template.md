# 最终结果与交接报告模板

## 适用场景

当一轮跨仓 ADR 实施、偏离修复或部署验证结束时，使用 `result.md` 或 `HANDOVER.md` 保存稳定最终结论。当前进展、下一步和阻塞仍由 Beads issue 承载。

## 推荐结构

```markdown
# <专项名称>最终结果/交接

- **日期** → YYYY-MM-DD
- **目标分支** → 脱敏后的分支信息，或不记录
- **范围** → 仓库和 ADR

## 一、总览

- **仓库** → 变更/评审、编译、单测、部署/E2E、状态。

## 二、ADR 决策与代码核对

- **ADR 决策** → 代码落点、证据、结论。

## 三、偏离与 FIX 结果

- **FIX/用例** → 归属 ADR、修复状态、证据、剩余风险。

## 四、测试与构建

说明命令、JDK/包管理器、模块、结果和既有失败。

## 五、跨系统/API/DB/UI/E2E 验证

说明操作、关键字段、预期、实际、证据和数据还原。

## 六、部署与回滚

只记录已授权并实际执行的动作；写实际产物、rollout、日志、API 和回滚入口。

## 七、未完成项与技术债务

区分代码缺陷、数据依赖、环境阻塞、明确不开发和后续 task。

## 八、关联 ADR 与 Beads

列出 ADR、已完成 task、未完成 task 和长期 memory key。
```

## 写作规则

- 结果报告是事实汇总，不是进度日志。
- 每个“通过”必须有对应证据；每个“未完成”必须有原因。
- 不粘贴密码、Token、私钥、完整连接串、Cookie、Authorization header、真实敏感环境值或未经脱敏用户数据。
- 不把 commit/push/部署成功等同于业务验证成功。
- 交接报告保留下一位执行者需要的入口，但运行时环境仍以实际配置和实时查询为准。
- 失败、未开发项、技术债务、数据依赖和环境阻塞必须保留，不为追求全绿而删除。
