# Interview Skill — 决策采访技能

## 何时使用

满足以下任一条件时，触发本技能：
1. Owner 说"逐项采访我"、"逐条采访"、"一个个确认"
2. 需要 Owner 做决策，且有 ≥1 个可选方案
3. 架构师向 Owner 征询技术/产品/资源决策

**不适用于**：纯信息查询、状态汇报、无需决策的进度同步。

---

## 核心流程

```
1. 【收集】把待决策问题整理成结构化选项
2. 【制卡】每个问题 → 一张飞书消息（文字列表形式）
3. 【发送】通过 message 工具发出文字消息
4. 【等待】Owner 回复字母（A/B/C）或直接说想法
5. 【闭环】每个决策结果 → 记录到 AGENTS.md / 更新 ADR
```

---

## 消息格式

每次只发一个问题，用文字列表形式：

```
📋 决策采访 — Q{序号}

**背景**: {为什么这个问题需要现在决策，对项目有何影响}

**现状**: {当前状态/已有的方案/已有哪些约束}

请选择：
[A] {选项A描述}
[B] {选项B描述}
[C] {选项C描述}

影响: {如果不选，任何一个选项的潜在风险是什么}
```

---

## 交互协议

### Owner 响应方式
- 直接回复字母：`A` / `B` / `C`
- 或直接说想法：_"我觉得A更合适因为..."_
- 不强制要求字母，文字回复也视为有效决策

### 一个一个问题来（关键约束）
- **每次只问一个问题**，等 Owner 选择后再问下一个
- 禁止一次发出多个决策问题
- 禁止在消息中同时问多个问题

### 决策结果记录
每次 Owner 选择后，立即记录：
```
Q-{序号}: {问题标题}
→ 决策: [{选项字母}] {选项描述}
→ 决策时间: {HH:MM}
→ 落地位置: {ADR文件名或章节}
```

---

## 快速采访模板（适合连续多个决策）

如果有一系列相关决策，连续发多个问题：

```
📋 决策采访（共 N 项）

## Q1: {第一个问题标题}
背景: {背景}
现状: {现状}
请选择：
[A] {选项A} → {选A后的方向}
[B] {选项B} → {选B后的方向}
[C] {选项C} → {选C后的方向}
影响: {风险摘要}
---
## Q2: {第二个问题标题}
...
```

---

## 常见错误

| # | 错误 | 正确做法 |
|---|------|---------|
| 1 | 一次问 3 个问题 | 一次只问 1 个 |
| 2 | 选项描述太抽象（"方案A"） | 选项描述具体方向 + 结果 |
| 3 | 没有说清楚背景和影响 | 三要素必须完整 |
| 4 | Owner 没回复就跳过继续 | 等 Owner 回复再推进 |
| 5 | 决策结果没落地到文档 | 立即更新 ADR/AGENTS.md |

## 示例对话

**架构师**: 
> 📋 决策采访 — Q1
> 
> **背景**: T-M2-013 热更新方案需要确定实现方式，这会影响 API 网关和配置中心的改动范围。
> 
> **现状**: M1.4 已有静态配置读取机制，无热更新能力。
> 
> 请选择：
> [A] PUT API 更新 JSON 后主动刷新内存缓存（不改配置中心）
> [B] 引入配置中心（Apollo/Nacos）管理配置
> [C] 热更新暂不上线，记录技术债务
> 
> 影响: 选 B 会显著增加 M2 开发复杂度；选 C 影响后续 M3 验收。

**Owner**: A

**架构师**: 
> ✅ Q1 决策：A（PUT API 刷新内存缓存）
> 
> 📋 决策采访 — Q2（下一个问题）

## 与 task-publish 的关系

- **task-publish** 管"任务怎么调度执行"
- **interview** 管"架构师和 Owner 之间的决策闭环"

两者结合：Owner 通过 interview 做决策 → 架构师通过 task-publish 调度执行。
