# 功能矩阵（MATRIX）模板

## 核查结论总览表

```markdown
# {项目名称} — 功能矩阵

**文档状态**: v{digit}.{digit}
**核查日期**: {YYYY-MM-DD}
**核查来源**: T-{ID} 三路并行审查（FE/BE/AL）
**知识库**: specs/FEATURE-INVENTORY.md

---

## 核查结论总览

| 维度 | 核查功能数 | 🟢存在 | 🟡弱化 | 🔴缺失 | ⚪Phase2 |
|------|-----------|--------|--------|--------|---------|
| 前端（FE） | N | N | N | N | N |
| 后端（BE） | N | N | N | N | N |
| 算法（AL） | N | N | N | N | N |
| **合计** | **N** | **N** | **N** | **N** | **N** |

**FIF（功能实现完整度）**: N/N = **XX%**
**FDI（功能偏差指数）**: X.XX
```

## 模块级矩阵表

```markdown
## 一、模块{N}：{模块名称}

| 功能ID | 功能名称 | BE | FE | AL | 综合状态 | 严重度 | 说明 |
|--------|---------|----|----|----|---------|--------|------|
| N.N.N.N | 功能点名称 | 🟢存在 | 🟡弱化 | 🔴缺失 | 🔴缺失 | P0 | {简要原因} |
```

## 状态说明

| 状态 | 含义 | 判定规则 |
|------|------|---------|
| 🟢存在 | 完全符合规范 | BE路径匹配+Service完整，FE字段全，AL阈值达标 |
| 🟡弱化 | 部分实现或功能降级 | 任一维度弱化 |
| 🔴缺失 | 规范要求但未实现 | 任一维度缺失 |
| ⚪Phase2 | 架构决策，暂不计入 | 明确标注Phase2范围 |

## 每功能点详情条目

```markdown
### {FP-ID}: {功能点名称}

**规范要求**: {一句话描述规范要求}
**BE核查**: {状态} — {核查结论} — 证据: `{file}:{line}`
**FE核查**: {状态} — {人工核查结论（FE人工必填）}
**AL核查**: {状态} — {核查结论} — 证据: `{registry}:{entry}`
**综合状态**: 🟡弱化 | **最高严重度**: P1

**问题描述**: {BE/AL缺失/路径不匹配/字段不全等具体描述}
```

## 跨层断链标注（高优先级）

当发现BE↔AL、FE↔BE之间的调用链路断裂时，必须在矩阵中专项标注：

```markdown
## ⚠️ 架构断链（需专项修复）

| 断链ID | 从 | 到 | 问题描述 | 严重度 |
|--------|----|----|---------|--------|
| BL-01 | FE层 | BE层 | 前端调用`/quality`，规范要求`/datasets/{id}/quality` | P1 |
| BL-02 | BE层 | AL层 | Java后端无HTTP端点到Python算法平台 | P0 |
```
