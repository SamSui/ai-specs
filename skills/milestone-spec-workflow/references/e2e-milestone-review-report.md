# M3-MILESTONE-REVIEW-E2E-HONESTY-REPORT.md 格式规范

> 来源：`reviews/M3-MILESTONE-REVIEW-E2E-HONESTY-REPORT.md`（原始文档）
>
> **定位**：Milestone E2E 诚实评审报告，是 E2E 全量运行的 milestone 层面深度分析报告，为 E2E 覆盖分析和完成度报告提供**核心输入**。

---

## 文件命名

```
reviews/M{MilestoneNum}-MILESTONE-REVIEW-E2E-HONESTY-REPORT.md
```

**示例**：`reviews/M3-MILESTONE-REVIEW-E2E-HONESTY-REPORT.md`

---

## 必须章节

### 1. 文件头

```markdown
# M{Milestone} 里程碑评审报告 — E2E 全量测试诚实化专项

**评审日期**: YYYY-MM-DD
**评审范围**: M{x} 全部 E2E 测试（N 个 spec 文件，M 个测试用例）
**评审依据**: Docker Compose 全量 E2E 运行结果
**评审方法**: [简要描述评审方法，如"批量清理 `.el-*` 选择器、`networkidle`、假断言、状态码欺骗 → 全量运行验证"]
```

### 2. 一句话结论

```markdown
## 📌 一句话结论

**M{x} E2E 测试脚本"X%完成率"声明与真实运行结果存在[严重/部分]偏差。**

- 项目简报声称"[声明内容]"
- 实际全量运行：**A passed，B skipped（test.fixme），0 failed**
- **[X] 个测试用例之前靠[放宽状态码/路径错误]，"假装通过"**
- 后端 API 路径错误、未实现、内部 500 错误是根本原因
- **M{x} [能/不能]基于"诚实通过率"宣布封版**
```

### 3. 总体指标

```markdown
## 📊 E2E 全量测试结果（诚实化后）

### 总体指标

| 指标 | 数值 | 说明 |
|------|------|------|
| **Total** | N | N 个 spec 文件 |
| **Passed** | A | [通过类型分布，如"Browser Level 为主 + test-system-api 31 个"] |
| **Skipped (fixme)** | B | 诚实标记：[原因分类] |
| **Failed** | **0** | 零失败（无运行时错误）|
| **诚实通过率** | **A/N = X%** | passed / total |
```

### 4. 与修复前对比（如有）

```markdown
### 与修复前对比

| 指标 | 修复前（欺骗状态） | 修复后（诚实状态） | 变化 |
|------|-------------------|-------------------|------|
| Passed | A1 | A2 | ±N |
| Skipped | B1 | B2 | ±N |
| Failed | 0 | 0 | 不变 |
```

### 5. 关键发现（按严重程度）

每个发现必须含：
- **发现标题**：严重程度 P0/P1
- **问题描述**：具体说明
- **证据表格**：测试假设 vs 实际结果
- **影响分析**：对 milestone 封版的影响
- **修复状态**：✅ 已修复 / ❌ 未修复 / 🟡 部分修复

#### 发现模板：状态码欺骗（P0）

```markdown
### 发现一：X 个 API 测试"假装通过" — 严重程度 P0

**根因**：测试中 `expect([200, 401, 404, 500]).toContain(resp.status)` 把后端错误也视为"通过"。

**实际后端返回**：

| 测试中假设的 API 路径 | 实际返回 | 后端真实路由 | 根因 |
|---|---|---|---|
| `GET /api/v1/config/system` | 500 | ❌ 不存在（应为 `/api/v1/configs`） | **路径错误** |

**修复状态**：✅ 已清理所有状态码欺骗
```

#### 发现模板：API 路径不匹配（P0）

```markdown
### 发现二：API 路径前后端不匹配 — 严重程度 P0

**问题数量**：至少 **N 个** API 路径不匹配。

**典型案例**：

| 测试中路径 | 后端实际路径 | 根因 |
|------------|-------------|------|
| `/api/v1/config/system` | `/api/v1/configs`（复数，无 `/system`） | **路径错误** |
```

#### 发现模板：后端未实现或返回 500（P0）

```markdown
### 发现三：大量后端 API 未实现或返回 500 — 严重程度 P0

**未实现 API**：

| 模块 | 未实现 API | 影响前端功能 |
|------|-----------|-------------|
| 质量报告 | `GET /api/v1/datasets/{id}/quality/report` | 六维度雷达图 |

**返回 500 的 API**：

| API | 返回 | 可能原因 |
|-----|------|---------|
| `GET /api/v1/algorithms` | 500 | 数据库查询异常 |
```

#### 发现模板：正面发现

```markdown
### 发现四：[测试类型] 测试质量较好 — 正面发现

**通过的测试**：

| Spec 文件 | 通过数 | 说明 |
|-----------|--------|------|
| test-m2-config.spec.ts | 15/15 | 配置管理页面交互全部正常 |
```

### 8. 封版检查单

```markdown
## 📋 M{x} 封版检查单（诚实版）

| # | 检查项 | 要求 | 当前状态 | 阻塞 |
|---|--------|------|---------|------|
| 1 | 0 failed | E2E 全量运行无失败 | ✅ 0 failed | 否 |
| 2 | 无状态码欺骗 | 不允许 404/500/400/401 在断言中 | ✅ 已清理 | 否 |
| 3 | 核心功能 API 可用 | [具体要求] | ❌ 大量 500 | **是** |

**结论**：检查项 [N~M] 未通过，**M{x} [满足/不满足]封版条件**。
```

## 完整性检查

- [ ] 一句话结论含诚实通过率数字
- [ ] 总体指标含 Total/Passed/Skipped/Failed 四项
- [ ] 每个发现含证据表格（测试假设 vs 实际）
- [ ] 每个发现含修复状态
- [ ] 封版检查单含"阻塞"列
- [ ] 下一步行动分立即/短期/中期三档
- [ ] 附录含测试命令
- [ ] 禁止在正文中使用含糊表述（如"质量良好"、"基本完成"）
