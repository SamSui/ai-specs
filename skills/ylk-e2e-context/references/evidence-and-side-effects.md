# 通用 E2E 证据与副作用规则

## 验证层级

按任务风险明确实际完成的层级，不要把低层级证据写成高层级结论：

1. **代码核实**：实现和契约的静态关系一致。
2. **单元测试**：业务分支、空值、边界和持久化参数通过。
3. **构建/lint/typecheck**：对应仓库的真实命令通过。
4. **API/DB**：操作前后字段和跨系统状态核对。现有公共 E2E 脚本没有通用直连 SQL/DB 工具链；只读 DB 核对只有在实际工具存在时才可执行，不能作为默认能力假设。
5. **UI/E2E**：真实页面导航、点击、输入、弹窗和 DOM 断言通过。
6. **部署回归**：真实产物、workload、日志、API 和页面通过。

“代码已改”“API 返回 200”“页面没有抛异常”都不能单独代表 UI/E2E 完成。

## 业务断言

必须验证具体业务可观察结果：字段、状态、金额、时间、路由、文本、对象 ID 或上下游变化。断言对象由具体项目和测试用例定义，本 Skill 不预设任何业务对象或固定值。

以下断言不足以证明业务正确：

- 只检查 HTTP status 为 200。
- 只检查响应对象存在。
- 只检查页面没有 JavaScript 异常。
- 只检查点击动作没有抛错。
- 只检查列表或计数非空。

涉及数据变更时，至少核对：

```text
操作前关键字段
  -> 真实 UI 操作
  -> 操作后 API/DOM
  -> 必要时使用可用的只读数据源
  -> 上下游状态、时间、金额、规格、ID 等关键字段对比
```

不要把一个系统的字段名称、状态枚举或接口路径复制成其他系统的通用契约。

## 失败证据三件套

每条失败用例至少保留：

1. **截图**：能看到失败现场或验证区块；嵌入页面必要时截目标元素，而不是强行截宿主页面。
2. **API/网络摘要**：脱敏 URL、方法、状态码、请求/响应关键业务字段；不含 JWT、Cookie、完整 header 或完整 sessionStorage。
3. **明确 reason**：写清预期、实际、确认的页面身份/环境、数据前置条件和下一步定位方向。

正常通过的用例也应保留步骤、确认身份和关键业务断言。证据中的身份字段只用于审计，不是安全认证证明。

## 跨系统操作表

执行联动前建立最小表格：

- **阶段 1** → 页面身份：`<marker identity>`；UI 动作：`<click/fill/navigate>`；观察点：`<DOM/route>`；状态核对：`<read-only query>`；副作用：`<none or classified effect>`
- **阶段 2** → 页面身份：`<marker identity>`；UI 动作：`<click/confirm>`；观察点：`<message/status>`；状态核对：`<upstream/downstream>`；副作用：`<classified effect>`

页面身份必须逐阶段重新确认，不能因为前一阶段用了某个 Profile 就把它默认套给下一阶段。不同角色、环境和应用必须分别按 marker 选择页面。

## 数据夹具

需要制造或修改测试数据前，必须记录：

- 修改哪些数据以及为什么。
- 修改前的原值。
- 适用的用户、对象、环境和运行范围。
- 测试完成后的还原命令和顺序。
- 失败、中断或浏览器断开时如何避免脏数据。
- 已发生和计划发生的业务副作用。

记录真实数据库、真实对象、业务动作和外部回调的实际状态。只读查询可以绕过缓存确认事实，但不能以查询为名偷偷改变数据。

## 副作用记录

对以下动作记录实际是否发生、发生在哪个阶段以及产生的结果：

- 创建、提交、审批或状态变更。
- 签署、支付、外部回调或不可逆确认。
- 自动交付、数据传输、任务运行或资源创建。
- 导出、写入目标数据、修改配置或删除对象。
- 部署、触发 CI/CD、commit 或 push。

现有 runner 没有通用的副作用 deny-list、confirm hook 或 dry-run 机制。报告中应区分已执行、未执行、失败和被外部依赖阻塞的步骤，不把页面动作误写成业务结果。

## 结果措辞

使用能够区分证据层级的结论：

- “代码已实现，尚未部署验证。”
- “单元测试通过，跨系统字段尚未核对。”
- “E2E 失败，原因为数据依赖，不判定为代码缺陷。”
- “环境阻塞，未能完成验证。”
- “已完成页面操作，但后端结果尚未核对。”
- “接口通过，但没有完成真实 UI 流程，不能称为 E2E 通过。”

不要使用“全链路完成”“已解决”“测试通过”等宽泛结论掩盖未执行的步骤、弱断言、环境失败或历史数据问题。

## 安全边界

- `window.__YLK_PROFILE__` 是自动化识别协议，不是认证或权限依据。
- `127.0.0.1:9225` 拥有整个浏览器的控制能力，只允许受信任本机使用。
- 不把 JWT、Cookie、完整 `sessionStorage`、私有 header、密码、Token 或私有连接信息写入 Skill、日志、报告、Beads 或 Git。
- 读取历史手册、旧报告和 archive 脚本时，只提取稳定的自动化经验，过滤账号、密码、订单号、固定环境地址、旧端口和一次性业务数据。
