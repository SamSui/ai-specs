# 偏离与 FIX 映射模板

## 目的

把需求基线、改造前事实、架构决策、代码修改和验证证据连起来。参考 `docs/adr-resource-mgmt-deviation-fix/README.md` 的偏离总览和完整 FIX 映射表。

## 推荐记录格式

```markdown
- **用例/FIX** → TC-... / FIX-...
- **优先级** → P0 / P1 / P2
- **改造前差距** → 可复现事实和证据
- **归属 ADR** → ADR-NNN；若不归属，写明确不开发/范围外原因
- **最小修复/决策** → 代码或文档动作
- **实现状态** → 未开始 / 设计完成 / 已实现 / 记录不修 / 技术债务 / 数据依赖 / 环境阻塞
- **验证状态** → 未验证 / 代码核实 / 单测通过 / 编译通过 / API/DB 已验证 / UI/E2E 已验证 / 部署已验证 / 验证失败
- **代码落点** → repo/path:line
- **最后核验日期** → YYYY-MM-DD；未核验则留空
- **证据** → `类型：最小可追溯标识，YYYY-MM-DD`，例如 `test：DataProductRegisterReqProtocolTest 8/8，2026-08-12`
- **剩余风险** → 未验证项、回滚、数据或兼容性风险
```

## 状态定义

### 实现状态

- **未开始** → 已确认差距，但尚未设计或修改。
- **设计完成** → 决策、落点和验收要求已确认，尚未获实施授权或尚未编码。
- **已实现** → 代码或配置已按决策修改；不能推断为测试、环境或部署已通过。
- **记录不修** → 需求不属于本轮、原型要求原样照搬或用户明确不处理；写清理由。
- **技术债务** → 当前可接受但存在明确缺陷；记录根因、影响、触发条件和后续方向。
- **数据依赖** → 代码路径存在，但缺少可验证业务数据或夹具；不能写成通过。
- **环境阻塞** → 登录态、服务、权限、网络、部署或工具阻塞；保留失败证据。

### 验证状态

- **未验证** → 尚未执行有效验证。
- **代码核实** → 已检查实现与决策一致，但未执行测试。
- **单测通过 / 编译通过** → 仅表示相应自动化层级通过，仍需标明未覆盖的接口、UI 或环境。
- **API/DB 已验证 / UI/E2E 已验证 / 部署已验证** → 只记录实际执行并有证据的层级，不允许由低层级向高层级推断。
- **验证失败** → 保留失败事实、影响和后续处理，不得用“已实现”覆盖。

“已修复”不是单独的状态；仅当实现已完成，且当前任务所需验证层级已有对应证据时，可作为表格外的综合结论。

- **非架构操作** → 归入已有 ADR 的主题 README/FIX 表，不为每项局部改动创建 ADR。

## 映射原则

- 每个 P0/P1 用例和 FIX 都必须有归属：某个 ADR、明确不开发项或范围外说明。
- 一个 FIX 可以映射多个 ADR，但要说明每个 ADR 的具体依据。
- 一个 ADR 可以覆盖多个 FIX；正文保留稳定规则，README/结果报告记录细项。
- 实现状态不能只根据 commit 判断，验证状态也不能由代码状态推断；分别引用实际证据。
- 每条证据必须写明类型、最小可追溯标识和发生日期；提交引用提交日期，测试引用实际执行日期，API/UI/E2E/部署引用实际核验日期。
- 最后核验日期取该 FIX 最新有效证据日期，不得早于引用的提交、测试、接口或环境证据日期。
- 发现的新问题若改变架构语义、适用范围、跨仓契约或后果，新增或修订 ADR；若只是局部修复，追加 FIX。
- 不删除失败、未开发项、数据依赖或环境阻塞记录来制造全绿结果。

## 过程与长期知识

- 偏离表当前状态和处理进度 → Beads issue notes（使用 `bd update <id> --notes "<text>"`）。
- 已确认的偏离根因、稳定规则和重复踩坑 → Beads memory（使用 `bd remember`）。
- 主题最终偏离清单与实现/验证状态 → ADR README 或偏离矩阵。
- 提交、测试、CI/CD、部署、E2E 的完整证据与交接 → `result.md` 或 `HANDOVER.md`。
- ADR 正文仅保留支撑决策的状态摘要，不重复执行过程。
